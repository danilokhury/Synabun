# Codex Sidepanel — Full Feature Parity Plan

**Constraint**: All changes isolated to `ui-codex-panel.js` and the Codex bridge section of `server.js`. ZERO modifications to `ui-claude-panel.js` or any Claude-specific code. Shared utilities (copy buttons, path links, etc.) duplicated inside Codex panel — no cross-imports.

**Files modified**:
- `neural-interface/public/shared/ui-codex-panel.js` (client)
- `neural-interface/server.js` (Codex bridge only, lines ~2178-2691)
- `neural-interface/public/shared/styles.css` (Codex-specific CSS classes only, `.cxp-*` prefix)

## Phase 1: Header Toolbar — Model, Effort, Plan, Auto-Accept

### 1A. Model Selector Dropdown
- Add new RPC method `model/list` to the server bridge (send to app-server, forward response to client)
- Add `model/list` client message type in `handleCodexSkinWebSocket`
- Add `.cxp-model-dropdown` in the header bar (after project selector)
- Fetch model list on panel open + cache per-connection
- Store selected model per-tab in tab state (`tab.model`)
- Pass `model` param to `turn/start` and `thread/start` RPC calls
- Display context window size next to model name
- Persist last-used model in storage key `synabun-codex-panel-model`

### 1B. Effort Toggle
- Add `.cxp-effort-toggle` button in header toolbar (4 levels: off/low/medium/high)
- Visual indicator: animated dots + underline scale (like Claude's think toggle)
- Store per-tab (`tab.effort`), persist in `synabun-codex-panel-effort`
- Pass `effort` param to `turn/start` RPC
- "off" = omit effort param (server default)

### 1C. Plan Mode Toggle
- Add `.cxp-plan-toggle` button in header toolbar
- When active, prepend plan-mode instruction to turn input
- Visual indicator: plan icon with active state CSS
- Store per-tab (`tab.planMode`)
- No SDK plan-mode flag exists — implement via prompt injection in `turn/start` input

### 1D. Auto-Accept Toggle
- Add `.cxp-autoaccept-toggle` button in header toolbar
- When enabled, automatically respond to ALL server requests (approval/input) with `accept` / `acceptForSession`
- Store per-tab (`tab.autoAccept`), persist in `synabun-codex-panel-autoaccept`
- Hook into `handleServerRequest()` — if autoAccept, send immediate approval response instead of rendering card
- Visual indicator: shield icon with active/inactive state

## Phase 2: Input Area — Attachments, Voice, Slash Hints

### 2A. Image Attachments
- Add `.cxp-image-strip` preview area above textarea
- Support paste (DataTransfer), drag-drop (overlay), click (hidden file input)
- Convert to base64 data URLs, store in `tab.attachedImages[]`
- Add `.cxp-attach-btn` with count badge
- Include images in `turn/start` input array as `{ type: 'image', image_url: { url: dataUrl } }`
- Remove button on each preview chip, max 5 images per message

### 2B. File Path Attachments
- Add `.cxp-path-chip` strip for attached file paths
- Store in `tab.pendingPaths[]`, render as removable chips
- Convert to absolute paths, include in prompt as path references

### 2C. Voice Input (Hold-to-Talk)
- Add `.cxp-mic-btn` next to send button
- Web Speech API: mousedown=start, mouseup=stop
- Append transcript to textarea, visual pulse animation
- Hidden if API unavailable

### 2D. Slash Command Hints
- Detect "/" at start of input text
- Render filtered hint dropdown (`.cxp-slash-hints`)
- Keyboard nav: Arrow up/down, Enter to select, Escape to dismiss

### 2E. Shift+Enter Interrupt
- When running: Shift+Enter sends current text as interrupt (additional context mid-turn)
- When idle: Shift+Enter = newline (default)

## Phase 3: Queue System

### 3A. Queue Tray UI
- Add `.cxp-queue-tray` at bottom of panel (above input area)
- Collapse/expand toggle with count badge, pulse on new item
- Pause/clear buttons, per-tab queue state (`tab.queue[]`)

### 3B. Queue Item Structure
```javascript
{ id: UUID, text: string, images: [], files: [], paths: [], timestamp: Date }
```

### 3C. Queue Operations
- Add to queue when sending while turn is running
- Draggable reordering, edit button (modal), remove button
- Pause/play toggle

### 3D. Queue Processing
- FIFO order, process next on `turn/completed`
- Auto-pause while awaiting approval, resume on resolution
- Send same way as single prompts (via `query` socket message)

## Phase 4: UX Polish — Copy, Links, Markdown

### 4A. Copy Buttons on Code Blocks
- After markdown render, scan for `<pre><code>` blocks
- Inject copy button (`.cxp-copy-btn`) top-right of each code block
- Click: `navigator.clipboard.writeText()` with icon swap feedback (2s)

### 4B. File Path Auto-Linkification
- Post-process rendered markdown: regex for filesystem paths
- Wrap in clickable `<a class="cxp-file-link">`, click copies path to clipboard
- Exclude paths inside code blocks

### 4C. Syntax Highlighting
- Load highlight.js from CDN (same version as Claude panel)
- Apply to code blocks with language class detection

### 4D. Markdown Rendering Throttle
- Verify existing `queueMarkdownRender()` throttles to ~30fps
- If not, add 33ms debounce timer for streaming deltas
- Flush immediately on `item/completed`

### 4E. Reasoning Block Improvements
- Collapsible by default (click to expand/collapse)
- Animated pulse dots during streaming (`.cxp-think-dots`)
- Summary parts as sub-sections

## Phase 5: Session Management Enhancements

### 5A. Session Locking
- Add `/api/codex-skin/session-lock` POST endpoint (isolated from Claude's)
- Lock on tab connect, release on close/unload/disconnect
- In-memory Map on server, keyed by threadId

### 5B. Thread Fork
- Add `thread/fork` RPC to server bridge
- "Fork" button in session menu, creates new tab with forked thread

### 5C. Thread Archive / Unarchive
- Add `thread/archive` and `thread/unarchive` RPCs
- "Archive" action in session menu, "Show Archived" toggle
- Pass `archived: true` to `thread/list` when toggled

## Phase 7: Server Bridge Enhancements

### 7A. Orphan Buffering & Reattach
- On WS close: keep child alive 30s, buffer messages into `_orphanBuffer[]`
- On new WS with matching threadId: replay buffer, reattach
- Use existing `codexOrphans` Map skeleton (~line 2697)

### 7B. Stall Detection
- Monitor time since last message during active turn
- Warn at 30s, kill at 120s, reset on every message
- Configurable per effort level

### 7C. Auto-Compact Detection
- Track token usage across turns from `thread/tokenUsage/updated`
- Detect >50% input token drop → synthetic `autoCompactDetected` event
- Client renders confirmation card

### 7D. Cost Estimation
- Estimate from token counts + hardcoded model pricing table
- Display in header as `~$X.XX` with tooltip
- Update on each `thread/tokenUsage/updated`
