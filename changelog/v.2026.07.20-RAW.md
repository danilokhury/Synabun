## 2026-07-19

### Fixed — Playwright Tab-Recovery Lifecycle Crash (Neural Interface)
- **Stale `beforeunload` dialogs no longer terminate the server** — `handleProcessFailure()` now delegates to `isIgnorablePlaywrightLifecycleError()` for the narrowly scoped `Page.handleJavaScriptDialog: Not attached to an active page` race at both the `uncaughtException` and `unhandledRejection` boundaries, while unrelated process failures remain fatal. `wireTabPageEvents()` retains defensive dialog handling until target retirement completes.
- **Wedged tabs recover without replacing healthy pages or leaking late resources** — `classifyBrowserPageError()` separates probe-worthy renderer failures from closed targets and ordinary `ERR_ABORTED`, `ERR_BLOCKED_BY_CLIENT`, or `ERR_FAILED` navigation errors. `recoverSessionTabPage()` bounds page/CDP creation, cleans resources that resolve after a timeout, verifies the replacement page, preserves tab ownership, and invalidates the full session when replacement cannot complete.
- **Invalidated MoreLogin sessions recover on the next pinned browser call** — Externally owned CDP sessions now use Playwright’s `browser.close()` transport teardown instead of the nonexistent `browser.disconnect()`. Recovery responses expose `sessionInvalidated`, and YouTube `safeNavigate()` avoids replaying navigation against the retired session; focused recovery tests pass 11/11 and the MCP suite passes 33/33.

### Fixed — Scheduled Bluesky Tabs Initialize on the Correct Origin
- **`bluesky_session` no longer reads storage from opaque schedule tabs** — Schedule-owned tabs are acquired at `about:blank`; `ensureBlueskyPageTarget()` now inspects the assigned tab’s URL, origin, title, and top-level state, initializes only blank tabs at `https://bsky.app/`, and verifies the final target before any XRPC evaluation. Valid Bluesky tabs remain untouched, while iframes and nonblank wrong-origin pages fail closed.
- **Session and posting paths fail safely** — `__bskySession()` converts blocked `localStorage` access into an actionable error, while `runBsky()` and `handleBlueskyPost()` preflight the target so posting cannot upload files or evaluate against the wrong page context.
- **Focused regression coverage protects tab isolation** — Added `mcp-server/tests/bluesky-target.test.ts` with five cases covering valid Bluesky tabs, blank-tab initialization, MoreLogin management pages, iframe rejection, and scheduled `bluesky_session` recovery; the complete MCP suite passes 38 tests.

- **Regression coverage exercises the real boundaries** — Concurrent MCP subprocesses verify one refresh and no shared-default mutation; native runtime tests verify persisted no-leak updates; the installed OpenCode CLI verifies concurrent final overlays beat conflicting project config; sidepanel contracts cover selectors, children, compact/reopen routing, legacy socket retirement, loops, and schedules.

### Fixed — Native Loop Launch Lag (Mac)
- **`NativeLoopRuntime.launch()` no longer blocks the HTTP response on a 20s `identityWaitMs`** — the previous contract waited up to 20s after the provider factory settled, just to learn the provider's session/thread ID. Identity now flows to the client through the existing `sidepanel:run-updated` WebSocket event as soon as the provider reports it (typically <1s for Codex and Claude). ### Fixed — Scroll-Bounce While Agents Stream (OpenCode / Codex / Claude Sidepanels)
- **Claude sidepanel auto-scroll fought manual scrolling** — `scrollEnd()` in `ui-claude-panel.js` had no user-scroll guard and yanked the viewport to the bottom from ~23 callsites, including the ~100ms stream-render throttle. ### Fixed — onnxruntime-node at-exit crash (`libc++abi: ... mutex lock failed`)
- **The scary `Abort trap: 6` on shutdown is gone.** SynaBun node processes were aborting at exit with `libc++abi: terminating due to uncaught exception of type std::__1::system_error: mutex lock failed: Invalid argument` (SIGABRT), generating recurring macOS crash reports. Root cause: local embeddings (`@huggingface/transformers` → `onnxruntime-node`) leave `ThreadPoolTempl::WorkerLoop` threads alive; on a normal `exit()`, `__cxa_finalize` destroys the threadpool's static mutex while those threads are still live → `std::terminate`. - **Fix:** every exit path routes through Node's `exit` event, which fires *after* all synchronous cleanup but *before* the C++ static destructors. The supervised-restart path keeps its `RESTART_EXIT_CODE` (75) exit instead of SIGKILL so the supervisor still restarts.
- **Also:** embedding pipelines now request single-threaded ORT (`session_options: { intraOpNumThreads: 1, interOpNumThreads: 1 }` in `local-embeddings.ts` + `lib/db.js`) to reduce the worker pool without changing vector output or latency. In non-interactive `run` mode OpenCode auto-**rejects** anything not explicitly allowed in `~/.config/opencode/config.json` (only the 7 SynaBun memory tools were), so accessing a sibling project (for example, `external_directory /Apps/OtherProject/*`) was denied and the iteration died (`✗ Read .env.local failed`). Added `--dangerously-skip-permissions` to the `opencode run` command, mirroring the Codex driver's existing `--dangerously-bypass-approvals-and-sandbox`.

### Fixed — Claude Code Loop Permission Prompts
- **Claude Code loops stalled on unanswerable permission prompts** — the loop PTY launched the bare `claude` binary via `getTerminalProfile()` with no `--dangerously-skip-permissions`, so accessing files outside the loop's working dir (or running `Bash`/`Write`) triggered interactive prompts the hook driver cannot answer. Added a loop-scoped `opts.loopBypass` flag that appends `--dangerously-skip-permissions` for the `claude-code` profile, and wired `loopBypass: true` at both loop launch sites (`/api/loop/launch` and the scheduled-launch path). Interactive terminal sessions deliberately omit the flag so manual sessions still prompt.

### Fixed — Loop Stall on Transient API/Socket Errors
- **A dropped API socket froze loops until the watchdog killed them** — `awaitingNext` (the flag that advances a loop) is set only by the Stop hook on clean turn completion. An `API Error: The socket connection was closed unexpectedly` aborts the turn without firing Stop, so the driver waited indefinitely. Added `detectTransientApiError()` (anchored to the CLI's `API Error:` label) plus a recovery block at the top of the `attachLoopDriver()` interval loop: when the error is detected at a ready prompt on an active loop, it re-injects a continuation prompt to resume the current iteration (no `/clear`, so context is preserved) under a 3-retry per-iteration budget; on exhaustion it force-advances to the next iteration by setting `awaitingNext`. The retry budget resets in `driveNextIteration()`.

### Fixed — Mutual Exclusion Same-Group Bypass
