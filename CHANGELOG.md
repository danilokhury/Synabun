# SynaBun v.2.0.7

2.0.7 brings the SynaBun desktop app for macOS, Windows and Linux, with updates that install themselves and a Windows installer that shows every step. SynaBun now finds every installed Claude Code, Codex and OpenCode the same way and installs a missing one with one click, you can sign in from the Claude and Codex panels, and the WhatsApp Assistant can send you files and understand voice notes.

## ✨ New

- **SynaBun desktop app** — The installers are now a real desktop app: SynaBun opens in its own window on macOS (Apple Silicon and Intel), Windows x64 and Linux x64, around the same server, runtime and interface as before. The window has SynaBun's own title bar instead of the system's: the window buttons sit at its right end on Windows and Linux, where a button at the left opens the menu, and the traffic lights sit inside it on macOS. Closing the window keeps SynaBun running; the app menu, the Dock or the tray bring it back. npm and Git installs are unchanged.
- **Updates that install themselves** — The desktop app checks the public releases shortly after it starts and every few hours. A newer version downloads at once. When SynaBun is idle, a one-minute notice with **Later** counts down, then the update installs, the window reopens as it was and a notice says what it updated to. While work is running it waits, and it also installs when you quit or at the next start. **Install now** is in the update dialog and the menus. If an update fails, the version you have keeps running, you get a link to download the new one yourself, and it tries again later.
- **A Windows installer that shows every step** — The installer lists each step as it goes, with the seconds since it started: the check for a running SynaBun, the unpacking with its progress, each part as it is put in place, the shortcuts and the **Settings → Apps** entry. The uninstaller lists its steps too, and the whole list is saved to a log you can open from the last page. If SynaBun is running, the installer asks once and closes it for you, letting the server shut down cleanly first; it never touches a SynaBun installed with npm or Git. Installing is faster: the files are unpacked straight into place, and the app carries about 6,600 fewer files. An install counts as finished only when every file is in place, and an update that cannot finish leaves the version you have running. Updates from the app stay silent.
- **See what the desktop app is doing while it starts** — **Details** on the start screen shows a live log of the start: the checks, the browser download with its progress, the build and the server's first lines. It opens by itself on the first start and when something fails, and keeps the real error. In the setup wizard, **Details** under Environment Check and Install & Build show the commands that ran with their answers, and what the app came with.
- **npm and npx come with the desktop app** — They work even when your computer has no Node.js. Your own npm and tools always come first; the bundled ones are only a fallback, and their global installs go to a folder in SynaBun's data folder instead of into the app, unless you set an npm prefix of your own.
- **Git Bash for Claude Code on Windows** — On a Windows PC without Git for Windows, Claude Code ran its hooks in PowerShell, where SynaBun's hooks do not work. SynaBun now brings its own unchanged copy of Git for Windows and uses it only when your PC has none: the Windows installer carries it, and an npm install on Windows downloads it once and checks it against a pinned checksum before unpacking it. A Git you installed yourself always wins, and **Settings → AI connections → Executable paths** shows which one Claude Code gets.
- **Settings → About** — A new last page in Settings shows your version and how SynaBun is installed, with **Check for updates** and **Copy info** (version, install type, Node.js, SQLite, the desktop app's Electron and Chromium, your system and the dependency versions; no paths, ports, keys or settings). It also has the project's links, system details and every dependency with its version and license.
- **SynaBun finds your Claude Code, Codex and OpenCode** — The side panels, Settings and every launcher find each CLI the same way: the path you set in Settings first, then your PATH as a new terminal sees it, then the folders the official installers use. A CLI that is found but does not start shows its real error instead of "not installed".
- **One-click install of a missing CLI** — When Claude Code, Codex or OpenCode is not installed, its panel shows a banner with **Install**, which runs the vendor's official installer for your system and shows its progress, next to the manual command and the install guide. The OpenCode panel gets this banner too. **Add to PATH** makes an installed CLI available to new terminals.
- **Sign in from the Claude and Codex panels** — `/login` and the new account button open a sign-in card that drives each CLI's own sign-in: open the sign-in page, finish in your browser, and the panel shows who is signed in. Codex also offers a device code. Tokens stay with Claude Code and Codex, SynaBun stores none, and sign-in cards are never saved into stored chats.
- **Auto · most usage left** — Claude Code and Codex routes and the composer's model menu can pick the subscription account with the most usage left. Usage windows show beside each account, and an exhausted account falls back to another one of the same provider.
- **The WhatsApp Assistant can send you files** — Ask for a file on your computer and the Assistant sends it to your WhatsApp chat as a real attachment, with an optional caption: pictures, videos and audio as such, anything else as a document with its name. Files go only to your own chat, files over 100 MB are refused, and SynaBun's own data, your WhatsApp session, your AI tools' settings and keys, and system folders are never sent, whatever path leads to them.
- **WhatsApp voice notes** — Voice notes and audio messages can now be transcribed on your computer and reach the Assistant as text. Turn on **Transcribe voice notes** in **Settings → Messages → WhatsApp**; it uses your own FFmpeg and whisper.cpp with a model you provide, and no audio leaves your computer. The status line says what is missing. A transcribed note is never taken as a command or an approval, and typed commands such as `/stop` never wait behind one.
- **Language and showcase addresses** — Adding `?lang=pt-BR` to the interface's address opens it in that language for that page only. `?showcase` opens it without saving any change to your layout and blurs your memories, sessions, transcripts, terminal output and other personal content, for screenshots and recordings.

## 🛠 Fixed

- **A named Claude profile could run as another account** — A side-panel tab on a named Claude profile could run with the credentials SynaBun itself was started with. It now runs only under its own profile.
- **Codex could start without SynaBun's tools** — The panels, the Assistant, workers, schedules and loops now register SynaBun's MCP connection with Codex when it is missing, without replacing one you connected yourself.
- **Terminals did not see newly installed tools** — Every new terminal reads the current system PATH, so a CLI installed after SynaBun started is found.
- **The MCP server reported version 2.0.0** — It now reports SynaBun's real version.
- **The WhatsApp link stopped after a connection error** — The link no longer gives up on its own after a stream or connection error from WhatsApp, a burst of reconnects or repeated restarts of the connector. It keeps retrying with your saved session and recovers without **Reconnect**, and stops only when WhatsApp says the session is no longer valid.
- **Answers to WhatsApp got lost when a task moved to another model** — When the Assistant continued a task you sent from WhatsApp on another model, its answer did not reach your phone. It now comes back once to the chat that started it.
- **The memory search sat under the menu** — In the Map view, above all in Portuguese, the search field was drawn under the menu labels and could not be used. It now has its own place in the bar at every width and in every language, and turns into a search icon when there is little room.

## ⚙️ Changed

- **One Assistant budget per session** — Five separate caps are replaced by one budget per session, or **No limit**. The Budget chip next to Project sets it for a new session, and the spend chip, the Budget menu and `/budget` show how it is shared between Claude Code, Codex and OpenCode and what is left. When one provider's share runs out, the rest is rebalanced.
- **The Assistant mascot follows Project and Budget** — It looks at the Project and Budget chips you point at, and reacts once when a budget is saved.
- **A dispatched run's time limit counts work time only** — The limit of a run the Assistant dispatches now runs only while the worker is working. Time in the queue, idle time between follow-ups and time waiting for your answer to a permission or a question no longer use it up, so a late follow-up is not cut off midway. The limit is never below 20 minutes.
- **WhatsApp Autonomous stays on until you turn it off** — Autonomous no longer ends after 8 hours: it stays on until you lower it in Settings. `/pause` pauses messages and `/stop` stops the current task, and neither changes the level. A level that was turned on under the old 8-hour rule comes back as Ask after the update.

# SynaBun v.2.0.5

2.0.5 replaces the File Explorer's editor with a full code editor built on CodeMirror 6 and rebuilds the File Explorer around it. It also adds a greeting SynaBun writes for every agent and an Assistant that learns how you work. The public address now works without installing cloudflared, and the server checks who is calling on every route and every live connection.

## ✨ New

- **Code editor on CodeMirror 6** — The editor that opens from the File Explorer is rebuilt and ships with SynaBun. Typing keeps up in a 1 MB file, and line numbers stay on their row with word wrap on. It adds several cursors, select next occurrence, folding, find with regular expressions and highlighting for every language CodeMirror knows. Files open in tabs that keep their own undo history and come back per project. Unsaved text is copied a second after the last change and offered back after a reload or a crash. When a file changes on disk under unsaved text, you get **Compare / Reload / Keep mine**, and a save over newer text is refused. Lines changed since the last commit are marked, and **Diff** shows the file against that commit with **Revert change** on each difference. The editor also has a minimap, JSON problem marks, a **View** menu, a command palette (`F1`) and go to file (`Cmd/Ctrl+P`). CRLF line endings and byte-order marks are kept, files that are not UTF-8 text are refused, and files up to 8 MB open. Preferences are in **Settings → Code editor → Editing**. `Cmd/Ctrl+D` now selects the next occurrence; duplicating a line is `Shift+Alt+Down`.
- **AI autocomplete in the code editor** — Grey text appears after the caret when you pause; `Tab` accepts it and `Esc` dismisses it. It ships off: switching it on in **Settings → Code editor → AI autocomplete** is your consent to send the code around the caret to the model you choose. Files on the editable **Never sent** list (`.env`, keys, certificates) and text that holds a private key are never sent. Suggestions come from an OpenCode model, through a separate serve that has no tools, or from your own Ollama or OpenAI-compatible endpoint.
- **File Explorer rebuilt** — The tree follows the disk: what an agent creates, changes or deletes shows within a second or two. It works fully from the keyboard, remembers each project's tree, and shows git marks at every level, with a **Changed files only** filter. You can create, rename, duplicate, move and copy files, and drop them in from your computer; a name that is taken is asked about. **Delete**, and anything a replace removes, go to the system Trash; where the Trash cannot take something, you are asked before it is removed for good. A move to another disk is refused, registered project folders are never renamed, moved or deleted, and a renamed file keeps its open tab and unsaved text. **Send to…** hands files to Claude Code, Codex, OpenCode or the Assistant. A click on a file opens its menu, as before; a double-click opens the file.
- **File links open in the code editor** — In the Assistant, Claude Code, Codex and OpenCode panels, a link to a text file opens it in the code editor at its line and column (`:12:3`, `#L12`). If the editor cannot open a path, a toast says why.
- **A greeting written by SynaBun, for every agent** — When you come back to a project after an hour away, a fresh session opens with a sentence or two: what you were doing, what was left open, and what finished or failed meanwhile. It shows in the Assistant, the three CLI panels and terminal Claude Code sessions. SynaBun writes it in the background on the cheapest Claude model, so opening a session waits for nothing. **Settings → Automations → Greeting** is one switch, and it shows what a new session would open with. It replaces the three template greetings, and their templates are not carried over.
- **The Assistant gets to know you** — **Settings → Automations → Automation behavior** has three switches. **Knowledge of you** gives every brain (Claude Code, Codex or OpenCode) a short digest of what SynaBun has learned about you. **Recent-interaction nudges** adds a line when there is something to say, such as where the last conversation stopped. **Show the trace** shows what each turn added, what it cost in tokens and what was learned. Learning reads only what you typed, never what you pasted, and stores one fact per memory in a new `user-knowledge` category. Learning needs AI decisions (a TypeSafe key).
- **cloudflared comes with SynaBun** — **Start tunnel** now works without installing anything. The installers carry cloudflared. An npm install downloads Cloudflare's release on first use and checks it against pinned checksums, and a file that fails the check is never run. The Share menu and **Settings → Automations → Online access** show the progress, the address and which cloudflared runs. A failure comes with **Try again**. A cloudflared on your PATH is used only when a download is not possible.

## 🛠 Fixed

- **A dispatched worker's tab ended on an error line, or on nothing** — Each worker tab now ends with one card: **Task complete** with the result, time and cost, or **Blocked**, **Needs input**, **Task failed** or **Stopped** with the reason. **Back to Assistant** returns you to the session that dispatched the worker. Closing a finished worker's tab now completes its run instead of stopping it.
- **Restart Server looked like a hang** — **Apps → Restart Server** now shows the restart screen at once and lists each step until the app reloads; other open windows follow. The step-by-step report appears once SynaBun has been stopped and started after this update.
- **Renamed Assistant sessions were listed under their first prompt** — They are now listed and reopened under their new name, also by `/resume`.
- **Only one open Assistant session animated** — Every session's mascot now moves at the same time.
- **Model lists missed models the panels offered** — Model routes and the Assistant's model menu now follow each provider's own list, minus the models you hid, and update without a reload.
- **A hidden alias hid whatever model it later named** — Hiding `haiku` also hid the newer model once Claude Code moved the alias to it. A hidden alias now hides the model it named when you hid it.
- **Invite guests could reach some routes meant only for you** — Admin-only areas, MCP server credentials, skill installs and the git routes are now closed to guests, however the address is written. A visitor through a custom invite address needs an invite session. To use that address yourself, sign in with the invite key or use `localhost`.
- **Reading a repository could start its programs** — Git reads no longer start programs named in a repository's own configuration, such as a file-system monitor, hooks or an external diff tool. A commit still runs its hooks.
- **Smaller fixes** — A cookie with a stray `%` from another app on `localhost` no longer breaks every request. Memory chips in the Assistant panel open their memory. Deleting an empty folder in the File Explorer works.

## ⚙️ Changed

- **The server checks who is calling** — Everything under `/api`, the MCP endpoint and every live connection now answer only requests addressed to this server. That means `localhost`, an IP address, this computer's own names (its `.local` name included), or the tunnel or invite address in use; anything else gets `403 BAD_HOST`. If you reach SynaBun under another name (a `.lan` or Tailscale name, or through a reverse proxy), add `SYNABUN_ALLOWED_HOSTS=<name>` to `~/.synabun/.env`. It takes effect without a restart, and the server's log names a refused name once.
- **Remote MCP needs its access key** — From the tunnel, a custom invite address or another machine on your network, the MCP endpoint answers only at `/mcp/<access key>`. While no key is set, it does not answer them at all. On this computer `/mcp` works as before. Only SynaBun's own pages on this computer can start or stop the tunnel.
- **Workspace toolbar** — The top-right toolbar is one compact row: the workspace switcher first, then the tools, a **»** toggle that shows or hides them, and the side-panel buttons. **Hide all toolbars** is gone. Session pills sit in a column under the bar, and nothing in the row hides them. **Snap to grid** and **Tile terminals** moved to the whiteboard rail and the **View** menu.
- **Model routes explains each mode** — **When to ask** is a radio group. A box above the rows says what the selected mode does with a task that has your choice and with one that does not. Routing itself is unchanged.

# SynaBun v.2.0.4

2.0.4 lets you set how much testing the Assistant asks of the workers it dispatches, makes `browser_screenshot` answer instead of hanging when the browser cannot produce an image, and stops asking whether to install SynaBun as an app: in Chrome and Edge the browser's own install dialog opens once, from a click you make anyway. It is the first release since 2.0.0.

## ✨ New

- **Test density for the Assistant** — A three-bar gauge next to the permission mode in the Assistant's composer sets how much testing dispatched workers are asked to do. **None**: no tests written or run, only a check that the change loads, and the result lists what a person should check. **Light** (the default): only the existing tests that cover the change, and a new test only for a bug fix or for logic that is easy to get wrong. **Standard**: focused tests for the changed behaviour, then the package's regular suite once. **Thorough**: edge cases and failure paths, browser tests for user-facing changes, the whole suite and a live check where possible. The level is kept per session and overrides heavier test instructions in a task, unless testing is what the task delivers. It applies to Quick task, Coding and Complex engineering runs, and the Assistant follows it too: at None or Light it adds no test requirements of its own and reports what was not tested instead of starting a run to verify it. Conversations from WhatsApp run at Light.
- **Automation tabs can open behind your work** — With `"openTabsInBackground": true` in `browser-config.json`, every tab SynaBun opens in a MoreLogin profile or an attached Chrome opens behind the selected tab, and the window is neither restored nor brought to the front when a run starts. Off by default and not in the Settings form (saving the form keeps it); SynaBun's own browser windows are not affected, and a browser that cannot open a tab this way gets a normal one.

## 🛠 Fixed

- **`browser_screenshot` could hang until the caller timed out** — The selected tab of a minimized window, or of a hidden application, does not answer a screenshot command; the tool waited out the whole request and returned a bare timeout, and a capture with a custom size could leave the tab at the capture's size. A capture with no answer in 8 seconds (1.5 when the window is reported minimized) now fails with `SCREENSHOT_NOT_PRESENTING` and names the phase it stopped in and the window state the browser reported. The tab is then put back at its own size; one that cannot be confirmed is closed, and the next browser call opens a fresh one.
- **Closing tabs could leave a browser session pointing at a closed page** — When the tab chosen to take over was itself closed while the switch was under way, the session kept a page that no longer existed. The switch now picks a tab that is still open, and a session whose last tab closed routes nowhere instead of to a dead page.

## ⚙️ Changed

- **SynaBun no longer asks about installing as an app** — In Chrome and Edge, the page the desktop launcher opened, with its **Install as App** button and **Continue to SynaBun** link, no longer stops you: the browser's own install dialog opens once instead, from a press you make anyway. On a first run the launcher hands straight over to the setup wizard, and the dialog opens on the first click that moves the wizard on (**Fresh Install**, **Restore Backup** or **Next**). Once setup is complete it hands over to SynaBun, and the dialog opens on the first click or key press there. Accepted, dismissed or never offered, SynaBun goes on the same way.
- **The dialog opens once** — The wizard never opens it a second time, and after setup only the page load the launcher handed over opens it: a reload does not, and SynaBun in a normal browser tab never does. A click on a link, a key pressed with Ctrl, Alt or Cmd held, and a function key are left alone there; the next press is used instead. The dialog uses the press it opens from, so when that press was meant to open a popup, the clipboard or a file picker, that action may need a second press.
- **Apps → Install as App, Safari and other browsers** — The menu item is unchanged while the browser has a dialog ready. Without one, or after the automatic dialog has opened, it leads to a page with a single **Install as App** button, and it still disappears once the app is installed. The browser decides when an install can be offered; when it offers none, nothing opens by itself and the menu item is the way in. Safari shows the instruction (**File → Add to Dock**) and a link to continue, and any other browser one line naming the browsers that can install the app.

# SynaBun v.2.0.0

SynaBun 2.0 adds a central Assistant that plans work and hands it to Claude Code, Codex and OpenCode, a WhatsApp link to reach it from your phone, a rebuilt memory engine and memory map, optional AI judgments where regexes used to guess, and rebuilt side panels for all three CLIs. It is also the first release on plain semantic versioning.

> **Updating from 2026.x** — Versions used to be dates (`2026.9.5`) and are now plain semver (`2.0.0`). Installs older than 2.0.0 compare version numbers as they are, so their in-app update check does not offer this release. Update once by hand with `npm i -g synabun@latest`; your data is snapshotted on the first launch as usual, and from 2.0.0 on the in-app updater works as before.

## ✨ New

- **SynaBun Assistant** — A central orchestrator that opens with `a` (or **Apps → Assistant**) as a tab in the bottom command area or as a side panel. Pick its brain (Claude Code, Codex or OpenCode, with model, effort, account, project, MCP profile and permission mode); every turn recalls SynaBun memory, and tasks are dispatched to worker agents that run in the matching sidepanel and report back with a structured result. The `agents` MCP tool group (11 tools) is advertised only to the Assistant, so workers cannot dispatch workers.
- **Model routes** — Before it works, the Assistant proposes where a task should run: on its own model, or on a worker model chosen by task class, price and capability. A route mode (always ask, ask when unsure, never ask) decides whether you pick, saved routes are enforced, and any model of any provider can be switched off in **Assistant → Models**. Design runs only on a model confirmed to see images, and Image creation and Video creation only on models that can produce them; the files a creation run generates are collected into the run.
- **Clarifying questions, budgets and exact token accounting** — A vague request gets up to three multiple-choice questions before anything is dispatched, and workers receive your answers verbatim. A Budget window sets five money caps that hold for every provider and apply without a restart. A live gauge shows the session's tokens with input and output apart, priced from one list-price table.
- **Computer use on macOS** — Four `computer*` tools let the Assistant, and the workers it dispatches for it, see and operate desktop apps through a native helper compiled on first use. It is bounded by an app blocklist, protected windows, a password-field guard, a locked-screen refusal, one controller at a time and stop controls (the Stop button, `Esc`, the top-left failsafe corner), and the tools are advertised only to callers holding a desktop grant.
- **WhatsApp Link** — Chat with the Assistant from WhatsApp. SynaBun links as a *linked device*, the way WhatsApp Web does: no Meta developer account, no webhook and no server in between. Set it up in **Settings → Messages → WhatsApp** with a QR code or a pairing code, in your own "Message yourself" chat or with a second number; the connector is installed on demand. Three levels decide what a message may do: Read-only, Ask (the default: your phone approves each risky action) and Autonomous (8 hours, turned on only from the computer plus an `ALLOW` code from the phone). Computer use from WhatsApp stays off until you turn on its own switch. See [docs/whatsapp.md](docs/whatsapp.md).
- **AI decisions** — With a TypeSafe API key, SynaBun asks for a typed judgment where a regex or a similarity constant used to stand in for one: refusing restated memories and redacting credentials on `remember`, relations and replacements between memories, relevance on recall, stale memories when their files change, whether a turn is worth storing, whether a claim of success matches the output, trash triage, and advisory readings of browser pages. Every judgment has a working fallback, so nothing depends on the network; candidate secrets are masked before they leave the machine; and **Settings → AI decisions** has a master switch, a switch per surface, costs and a log of every judgment. Without a key, or with `SYNABUN_TYPESAFE=off`, nothing is sent. See [docs/judgments.md](docs/judgments.md).
- **Memory v2** — One local memory engine for the MCP server, the Neural Interface and the hooks: hybrid keyword and vector retrieval, passage-level refinement, compact token-budgeted results (`format: "compact"`), batch fetches, revision history with undo, retry keys that make a repeated `remember` return the same memory, and source verification. Existing memories and their UUIDs are kept; the migration takes a backup first.
- **The 3D view is a memory map** — A continent is a root category and an island is a category; inside an island similar memories sit side by side, and height is creation order. The map shows every memory (the old graph stopped at 8,000), places new ones as they are written, and renders only when something changes, so an idle map draws nothing. three.js ships with SynaBun; the map loads nothing from a CDN.
- **Style Guide** — A per-project brand and design system (colors in light and dark, type, spacing, shape, motion, components, rules) that writes `DESIGN.md`, W3C design tokens, CSS variables and a Tailwind theme, and imports from the same formats. Every agent gets it: dispatched workers find it in their brief, and the `style_guide` MCP tool answers with the summary, the tokens or a contrast check. Agents never edit the guide; they propose a change that you accept or reject. See [docs/style-guide.md](docs/style-guide.md).
- **Rules installed for you** — SynaBun's rules are one short ruleset per tool (Claude Code, Codex, OpenCode, Gemini, Cursor), installed where each tool loads them and kept up to date automatically. This replaces the template you pasted into `CLAUDE.md` or `AGENTS.md` by hand.
- **Claude Code sidepanel on the Agent SDK** — The panel now follows `@anthropic-ai/claude-agent-sdk` 0.3.288: every SDK event is shown, tool results are complete, reopened sessions keep their tool results, and sessions can be renamed, forked and deleted. Bypass is the SDK's real bypass mode and a tab is in it only by your choice. New: a temporary chat that leaves no transcript and stores nothing while recall still works, a rewind preview, and permission rules you can review and remove.
- **OpenCode sidepanel rebuilt** — Built against OpenCode 1.18.34: text streams as it is written, approvals queue instead of replacing each other, every sub-agent gets its own pill and panel, and shell mode opens with `!` on an empty composer. The legacy panel is removed.
- **Codex sidepanel on protocol 0.160** — Answers, terminal output and file diffs are formatted; plans are shown complete and open as that exact revision in the editor; MCP app views open inline behind a click and a per-call approval; attachments, gateway sign-in and user verification are supported.
- **Settings redesign, search and languages** — Eleven task pages replace twenty-two tabs, every section is a card, and a search field in the sidebar finds any page, section or control. A language selector adds Brazilian Portuguese.
- **Terminals in their own process** — A dedicated terminal host owns every shell, so typing no longer stutters while the server is busy. Output is flow-controlled, a reconnect restores colours, modes and the cursor, and shells start as login shells with truecolor.
- **Faster browser tools** — Bounded snapshots, server-side paged extraction, scoped content retrieval and `browser_batch` (several actions, one final observation) are on by default; `SYNABUN_BROWSER_V2=0` goes back. Cancelled or uncertain browser actions are never replayed automatically.
- **Recall before subagents** — In Claude Code, a Task or Agent dispatch now starts from a shared memory brief (5 memories, 1,200 tokens), so workers begin with the paths, earlier fixes and constraints the session already knows. On by default.
- **Claude accounts** — Several Claude accounts can be signed in side by side and chosen per session, the way Codex accounts already could.
- **A new workspace tour** — The **?** button opens a hand-drawn tour of memory and the map, the whiteboard, coding tools, browser and automations, and the Assistant. It resumes where you left off, in English and Brazilian Portuguese.
- **Start Server button** — When the server is down, the offline page and the app's Server Offline overlay show a **Start Server** button. It works on macOS, Windows and Linux, for npm and GitHub installs, starts one server however often it is clicked, and the page reconnects by itself when the server answers. While a start runs, the page names each step the launcher reports (installing dependencies, the browser download, the build, the pre-update backup, the server starting) next to a clock of whole seconds; a failed start shows its reason, the log's path and **Try again**. The command under the button is one line that works in cmd.exe, PowerShell and POSIX shells. A page opened through a tunnel, an invite link or a LAN address shows the clock and general status only.
- **Command Runner as a searchable library** — Saved commands can be searched by name, command, group or directory, filtered by group, and sorted by saved order or most recently run. Commands on a local workspace stay runnable without an internet connection.

## 🛠 Fixed

- **Any web page could open SynaBun's WebSockets** — Browsers apply no CORS to WebSockets, so a page open in the same browser could connect to `ws://localhost:3344/ws/*` (terminals, the Assistant, sync) and act as you. Every upgrade now checks its `Origin`: the request's own host, loopback on the port, or the configured tunnel or invite proxy.
- **Backups of large data homes failed and deleted themselves** — Verification read the whole archive into memory, which Node refuses above 2 GiB, and the failed archive was then removed. Verification now streams, and a backup folder on an unmounted drive reports that instead of a permission error.
- **A failed upgrade snapshot let the new version start anyway** — When the snapshot taken before a new version first runs could not be created, SynaBun warned and launched. It now stops before the server starts and says what failed and how to continue.
- **The updater could install a version other than the one it offered** — Click-to-update always asked npm for `latest`, so a beta install was moved to the stable release. It now installs exactly the version shown, and a release that npm does not have yet is a manual update.

# SynaBun v.2026.09.01

A Codex and memory-hooks release: Codex sidepanels no longer strand `already has an active writer` errors across tab switches, thread history moves off Codex's deprecated hydration path, and the Claude Code memory hooks stop re-issuing a block they were never able to clear.

## 🛠 Fixed

- **The "Unstored file edits" block never cleared** — A `remember` call without a `category` reset nothing, because the entire pending-remember reset was gated behind a branch that Claude Code rarely reaches: it routinely sends `remember` with `{ content }` alone. The flag was never cleared, so the Stop hook re-issued the identical block on every turn for the rest of the session — confirmed against a real session flag showing `rememberCount: 0` after four successful `remember` calls. The reset is now unconditional for any successful `remember` or `reflect`. Failure detection fails open by design: only an explicit `isError` / `success: false` / `status: "error"` counts as a failure, so a future payload change cannot silently reintroduce a block that never clears. A new `MAX_TASK_BLOCKS` session ceiling bounds the worst case.
- **Edit nudges never reached the model** — Every PostToolUse nudge was written as a bare top-level `{ additionalContext }`, but PostToolUse only reads `hookSpecificOutput: { hookEventName, additionalContext }`. The output was valid JSON, so it failed silently rather than erroring, and no "N file edits — remember to store this work" message was ever delivered. Fixed in `post-remember.mjs`, and in the five emission sites in `post-plan.mjs` that had the same bug — all now routed through one shared helper.
- **`reflect` was excluded by the hook matcher** — `post-remember.mjs` already handled `reflect`, but the registered PostToolUse matcher ended at `remember`, making that code unreachable: `reflect` calls never reached the hook. The matcher now covers both, anchored so it still never fires for `recall`, `memories`, or `forget`, and matches both Claude Code's `mcp__SynaBun__remember` and OpenCode's `SynaBun_remember` spelling.
- **Every hook invocation stalled about two seconds** — `readStdin()` resolved promptly, but its 2000 ms fallback timer stayed pending afterwards and held the event loop open, so each hook lingered for the full timeout before exiting — measured at 2.05 s against a configured 3 s hook timeout. Clearing and unref-ing the guard brings it to 0.02 s across every hook.
- **Memories were filed under the wrong project** — The MCP server read `claude-code-projects.json` from a data directory that has never existed, so registered project labels were silently ignored and every project fell back to a raw directory basename — `/Apps/MyShop` was stored as `myshop` rather than the registered label `shop`. Over the HTTP transport `process.cwd()` is the Neural Interface's own directory, which labeled every HTTP-sourced memory `neural-interface` regardless of the caller; that case now resolves to `global`, a recoverable mislabel rather than one indistinguishable from a real project.
- **Codex sidepanels stranded "already has an active writer"** — A tab's intentional socket close was invisible to the server, so it orphaned an idle Codex app-server for the full 30-minute grace period and the next `thread/resume` collided with SynaBun's own abandoned writer. Ownership is now handed back through a release handshake before the socket closes, retirement waits for observed process exit rather than a kill flag, and only connections with genuinely reattachable work — active turns, pending approvals, in-flight RPCs — keep the grace period. Rapid tab switching can no longer strand or resurrect a hidden writer, and a genuinely external writer still reports an actionable error instead of requiring a restart.
- **Codex thread history rode a deprecated hydration path** — Full history was requested through `thread/read` and `thread/resume`. SynaBun now rebuilds the same client shape by paging `thread/turns/list` and `thread/items/list` in chronological order, and falls back to paginated turns with `itemsView: "full"` when a store reports that item pagination is unsupported. Repeated cursors, invalid pages, duplicate ids, and items with no matching turn are rejected before they can loop or poison a transcript; timeouts and unrelated protocol failures still surface rather than being misread as compatibility gaps.
- **The Codex Resume dropdown blocked on a full account scan** — It now serves from the cached session catalog when rows exist and refreshes in the background, falling back to a full multi-account walk only when the cache is cold; the same cached catalog backs Codex search metadata. Windows path matching resolves with `path.win32` and compares case-insensitively, so drive-letter case and slash direction no longer drop valid sessions from project grouping. Cache warmup also starts earlier at boot, so the dropdown is usually warm by the time it is opened.
- **Agent-selected MCP profiles did not expose their tools** — Profile state was module-global even though the HTTP transport hosts multiple stateful MCP sessions in one process, so a profile switch could mutate the most recently registered server instead of the caller's. Each stdio process and HTTP client session now owns an isolated profile runtime. The `tools/list_changed` notification is also no longer emitted synchronously from inside `profile set` — where OpenCode could abort or discard the in-flight roundtrip — but delayed and coalesced until after the tool result returns, so newly enabled tools are usable within the same agent turn.
- **Codex could not call newly enabled tools mid-turn** — Codex snapshots deferred MCP tools when a turn starts, so a successful refresh updated the app-server inventory without making anything callable by the running agent. Canonical Codex registrations now start SynaBun with the full deferred catalog, while per-sidepanel and automation profiles remain isolated focus selections. Profile changes no longer trigger a global `config/mcpServer/reload` that restarted unrelated MCP servers and reported success before startup had finished, and repeating a valid `profile.set` now re-reports the runtime and emits a fresh notification so a strictly profiled host can heal a stale catalog.

## ⚙️ Changed

- **`remember` now requires `category` and `project`** — Both were declared optional in the tool schema, and the `category` description merely noted that "if omitted, a project default is used." Hosts took the hint and sent `{ content }` alone — which is exactly what left the Stop hook blocked. A JSON Schema `required` entry is enforcement; a description is advice, and the advice was already being ignored. `importance` stays optional, since nothing downstream depends on it. Category names that are present but misspelled are still remapped rather than lost.
- **The memory ruleset now states this accurately** — The shipped `CLAUDE.md` template claimed no recall-and-reflect was needed afterwards, without mentioning that omitting `category` misfiles the memory and leaves the stop hook blocked. Corrected across all six template sites, the README, and the `/synabun` skill modules. The ruleset version is now `1.2.0`, so existing installs are offered the update.
- **Installed hook matchers repair themselves at startup** — A matcher change previously reached fresh installs but left every existing `.claude/settings.json` on the old value indefinitely, because the startup sweep compared only the command string and short-circuited. It now compares the matcher too, counts repairs, reports them on the startup `Hooks:` line, and is idempotent — so a stale matcher cannot keep a hook unreachable across upgrades.

# SynaBun v.2026.07.34

A reliability release: the Claude sidepanel no longer dies with a misleading "does not match this system's libc" error, and every bundled native binary is checked and repaired at startup.

## 🛠 Fixed

- **"Native binary exists but failed to launch"** — The Claude sidepanel could fail every turn with *"Claude Code native binary at `…/claude` exists but failed to launch. This usually means the binary does not match this system's libc…"*. On macOS and Windows that explanation is never right: the real cause is almost always a missing execute bit. npm does not preserve the execute bit for files a package ships without a `bin` entry, which is exactly how the Claude Agent SDK and Codex deliver their native payloads, so a perfectly good binary can land as mode `0644` and fail to spawn. SynaBun now stats the binary the SDK is about to launch, restores the execute bit when it is missing, and retries — and when it cannot repair it, it says what is actually wrong: a permission problem on macOS and Linux, Gatekeeper quarantine (with the `xattr -d com.apple.quarantine` command) on macOS, a genuine libc mismatch only on Linux, and an unlaunchable `.cmd`/`.bat`/`.ps1` shim on Windows.
- **Only the current machine's binaries were repaired** — The startup repair looked at one directory, `prebuilds/<your platform>-<your arch>`, so a checkout carrying several platform builds left the others broken — including `darwin-x64`, which is what an Intel Mac needs for terminals. Startup and postinstall now sweep every vendored binary that is present (Claude Agent SDK, Codex, `node-pty`) by walking the tree instead of consulting a hardcoded list, so new platform directories are covered automatically.
- **The postinstall repair had stopped doing anything** — `scripts/rebuild-pty.js` was still fixing permissions on `node_modules/.bin/claude` and `@anthropic-ai/claude-code/cli.js`, neither of which has existed since that package was replaced by the Agent SDK. Its prebuild list named Linux directories that are not shipped while missing ones that are. It now runs the shared sweep, and runs it *before* the "node-pty not found, skipping" guard — previously an install without node-pty skipped the Claude and Codex repair entirely.
- **A `.cjs` executable override was launched the wrong way** — A custom Claude executable ending in `.cjs` was treated as a script to run through Node, but the SDK spawns it directly, so it needed the execute bit and did not get it.

## ✨ New

- **Runtime notices in the Claude sidepanel** — A new amber notice sits between grey status text and a red fatal error: something went wrong, was worked around, and the session is continuing in a degraded state. You will see it when the bundled binary is repaired and retried, and when a session falls back to your globally installed Claude CLI. It appears in both the sidepanel and the standalone chat page.
- **Fallback to your installed Claude CLI** — If the bundled runtime cannot be launched or repaired, sessions and unattended automation loops now fall back to the Claude CLI you have installed rather than failing the turn. Because model aliases and effort levels resolve per-binary, a version difference between your CLI and the bundled runtime is reported alongside the fallback instead of silently changing which model runs.

## ⚙️ Changed

- **A custom Claude executable path is now validated before use** — The `claude-skin` → `sdkExecutable` override was passed straight through to the SDK, which uses it verbatim with no checks of its own. It is now vetted first, and a bare command name such as `claude` is rejected with an explanation: the SDK spawns without a shell and cannot resolve a name from `PATH`, so handing one over produces a worse and more confusing failure than the one being recovered from. Overrides may be either a script entrypoint or a native binary path, and the same rule now applies to automation loops, which previously accepted anything.

# SynaBun v.2026.07.33

A Windows release: Codex schedules and sidepanels now find a globally installed Codex runtime instead of failing at launch.

## 🛠 Fixed

- **Codex could not be found on Windows even with the global CLI installed** — SynaBun located the Codex runtime by looking it up on the inherited `PATH`, and the PATH it built for that lookup only added POSIX directories (`~/.local/bin`, `/usr/local/bin`, `~/.npm-global/bin`) that do not exist on Windows. Started from anywhere whose environment did not already carry the npm global bin — a shortcut, a service, a fresh terminal after an install — Codex was invisible and every Codex schedule failed. Discovery no longer depends on `PATH` at all: `@openai/codex` is now located under `npm root -g`, `%APPDATA%\npm\node_modules`, an `npm_config_prefix` override, the `node_modules` directory that contains SynaBun itself, and Node's own install directory. The Windows PATH augmentation also picks up `%APPDATA%\npm`, the configured npm prefix, and Node's directory, deduplicated, so the shell-aware launch paths improve too.
- **The native Codex executable was missed under current npm layouts** — The resolver looked in exactly one place, `vendor/<target>/codex/codex.exe` inside the platform package resolved through `require.resolve`. Current Codex releases ship the executable at `vendor/<target>/bin/`, and depending on the npm version the platform package sits either beside `@openai/codex` or nested inside its own `node_modules` — and package `exports` can block the resolve entirely. Both vendor layouts and all three package locations are now checked directly, so hoisting differences no longer read as "Codex is not installed".
- **Windows launched npm's shell shim instead of the real launcher** — `npm install -g` writes both an extensionless `codex` sh shim and a `codex.cmd`, and `where codex` lists the shim first, which Windows cannot spawn. The sidepanel launch path now prefers a `.cmd`, `.exe`, `.bat`, or `.ps1` launcher and keeps the first result only as a fallback for non-npm installations.

## ⚙️ Improved

- **A missing Codex runtime says which problem it is** — The failure notice now distinguishes "the global Codex package is installed but its Windows runtime is missing" from "Codex is not installed globally", and both point at `npm install -g @openai/codex@latest --include=optional`. The platform executable ships as an optional dependency, so an install that skipped optional packages leaves a Codex that looks present and cannot run. Successful resolution logs which layout it came from, and failures log the candidate paths that were checked.

# SynaBun v.2026.07.32

A follow-up to 2026.07.31 that makes updating fast again on a large data home.

## 🛠 Fixed

- **Updating took several minutes on a large data home** — Before a new version starts, SynaBun snapshots your data home so the update can be rolled back. That snapshot archived *everything*, so a multi-GB data home spent minutes compressing during `npm install` — one report was 9,470 files and 3,832 MB. An upgrade snapshot only needs to protect state: it never rewrites your generated images, audio, or video, and those survive a rollback on disk regardless. Upgrade snapshots now skip generated media, and if what remains is still over ~1 GB they fall back to irreplaceable state only — your `.env`, everything under `mcp-data/`, and any `.db`, `.sqlite`, or `.json`. Compression on the blocking path drops to the fastest level, since what is left is SQLite and JSON that still shrink well. The snapshot reports what it skipped and why, and its manifest records whether it is `state-only` or `complete` so a restore can never mistake one for the other. Scheduled and manual backups are unchanged and still capture everything.
