## 2026-04-20

### Fixed — OpenCode CLI Update Command Fails With EACCES On macOS Root-Owned Global `node_modules`
- **`npm install -g opencode-ai@latest` blocked by filesystem permissions** — The prior "Unified CLI Update Commands via npm" unification set `UPDATE_COMMANDS['opencode']` in `neural-interface/public/shared/ui-tool-updates.js` to `npm install -g opencode-ai@latest`. On macOS installations where `/usr/local/lib/node_modules` is root:wheel-owned (the default when Node was installed via the official pkg installer), the unprivileged `npm install -g` cannot `rename` the staging directory into place and errors with `npm error code EACCES` / `permission denied, rename '.../node_modules/opencode-ai' -> '.../node_modules/.opencode-ai-<hash>'`, so the click-through update path from the badge silently failed when the user clicked it. Switched `UPDATE_COMMANDS['opencode']` to `'opencode upgrade'` — OpenCode's built-in self-update subcommand (visible in `opencode --help` as `opencode upgrade [target]  upgrade opencode to the latest or a specific version`). It detects the install method automatically (curl-install, brew, npm -g) and updates in place without requiring sudo or a user-owned node prefix (nvm/fnm/volta/asdf), so the badge's click-intercept now runs a self-contained update in the terminal shell tab that succeeds regardless of how OpenCode was originally installed.

### Fixed — Claude Sidepanel Compact Button Stuck "COMPACTING" On Fresh/Switched Tabs
- **Shared `#cp-compact-btn` DOM state never resynced to the active tab** — In `neural-interface/public/shared/ui-claude-panel.js`, the panel has one compact button shared across all tabs, but its visual state (`.compacting` class + `"compacting"` text + sweep animation) is driven by each tab's `tab.compacting` flag. `switchTab()` synced `viewMode`, queue, todos, gauge, etc. but never called `_setCompactingUI(!!tab.compacting)`, so if Tab A entered compaction and the turn never produced a terminal `done` / `aborted` / `error` event (WS disconnect, process killed silently), Tab A's `tab.compacting = true` stayed stuck AND any sibling tab — including brand-new chats created via the "New chat" button — inherited the visually-stuck "COMPACTING" pill. Added `_setCompactingUI(!!tab.compacting)` inside `switchTab()` just before `saveTabs()` so the button always reflects the newly active tab.
- **`finishTab()` didn't clear orphaned compacting state** — Only the inline handlers in `handleTabMsg` for `done` / `aborted` / `error` cleared `tab.compacting = false` (and only when the tab was active). If a tab's run ended via `finishTab()` from any other path — e.g., WS `close` during a compact turn, or the CLI process crashing mid-stream — the flag survived. Added a defensive `if (tab.compacting) { tab.compacting = false; if (tab === activeTab()) _setCompactingUI(false); }` clause inside `finishTab()` so the flag is guaranteed to reset when a tab's run terminates by any code path.

### Fixed — Terminal Tab Header Intermittent Clicks On Close (×) And Detach Icons During CLI Output
- **Tiny hit targets + rerender feedback loop during CLI busy-output** — In `neural-interface/public/shared/ui-terminal.js` the docked tab-bar click delegation checks `.term-tab-close` → `.term-tab-detach` → `.term-tab`, then falls through to `switchToSession(idx)`. `switchToSession()` unconditionally ran `renderTabBar()` (innerHTML replace) even when `idx === _activeIdx`, so a near-miss on the tiny `×` or detach SVG hit the tab body, triggered a redundant rerender, and the follow-up click landed on a stale DOM node (browsers drop `click` when the mousedown target is removed before mouseup). OpenCode / Claude Code streaming added mouseup-position jitter from main-thread contention, making the effect worse. Added an early-return in `switchToSession()` when `idx === _activeIdx` (ensures focus only, no `renderTabBar()`, no viewport swap) and an `idx === _activeIdx` short-circuit in the tab-bar click handler's `.term-tab` branch so a missed close/detach on the active tab is a true no-op.
- **Hit targets enlarged without visual change** — In `neural-interface/public/shared/styles.css` added `position: relative` + `::before { content: ''; position: absolute; inset: -6px -4px; border-radius: 6px; }` pseudo-elements on `.term-tab-close`, `.term-tab-detach`, and `.term-tab-dock` — extends the clickable area by ~6 px vertically and 4 px horizontally, overlapping into the tab's padding without moving siblings. Also added `pointer-events: none` to the inner `.term-tab-detach svg` / `.term-tab-dock svg` so `e.target` is always the `<span>` ancestor and `e.target.closest(...)` never walks out of an SVG `<path>` or `<rect>`.

### Fixed — Terminal Panel And Whiteboard Toolbar Left Margin Smaller Than Right Margin
- **`#terminal-panel` left inset bumped to match right inset** — In `neural-interface/public/shared/styles.css` the docked terminal had `left: calc(var(--sidebar-total-width, 0px) + 16px)` against `right: calc(var(--right-panel-width, var(--claude-panel-width, 0px)) + 20px)`, producing a visibly smaller gap on the left edge vs the right edge regardless of which sidebars were open. Changed the `left:` expression's constant from `16px` to `20px` so the free margin between the terminal and whatever is on its left (explorer/file-explorer edge or viewport edge) equals the 20 px gap against the Claude / Codex / OpenCode sidepanel on the right.

Changed to `left: calc(var(--sidebar-total-width, 0px) + 20px)` — same expression used by `#terminal-panel`, so the whiteboard toolbar and the docked terminal share a consistent left gutter.
