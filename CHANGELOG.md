# SynaBun Changelog

Raw internal changelogs are archived in [changelog/](changelog/).

## v.2026.5.3 — 2026-04-27 → 2026-05-03

### Added

- **Google Search Console MCP tool group** — 30 new tools covering every GSC section (URL Inspection, Performance, Pages / Videos / Sitemaps, Removals, Core Web Vitals, HTTPS, Security Issues, Manual Actions, Enhancements, Links, Disavow, Crawl Stats, Users, Associations, Shopping, screenshots) via Playwright-driven browser automation. No API key required — uses your authenticated Google session. Locale-tolerant selectors (English + Portuguese verified). Added a dedicated `gsc` profile preset and bundled into `full` and `browser`.
- **Notifications drawer** — Session Monitor reworked into a unified Notifications drawer with a new Updates tab for ruleset, SynaBun, and CLI-tool updates. Bell badge in the titlebar shows unread count and stays accurate via 5-minute polling without ever opening the drawer. Per-version ruleset alerts driven by a manifest so whitespace edits don't cause notification noise.
- **Loops tab** — Per-loop card with state badges (Running / Finished / Orphaned / Stale), live stalled timer, terminal alive/dead pulse, per-loop Stop button, and bulk Clear-stale / Clear-all controls. New `/api/loop/list` and `/api/loop/cleanup` endpoints; live `session:loops` WebSocket broadcast.
- **Sidepanel kill-on-close** — Closing a tray pill now force-kills the underlying Claude / Codex / OpenCode session immediately rather than waiting for the orphan grace timer.
- **OpenCode model capability explainers** — Inline help strip describes each capability (Reason, Tools, Vision, Audio, Video, PDF, ImgGen, TTS, Files) on chip hover, focus, or active filter. Replaces overlapping floating tooltips.

### Changed

- **OpenCode markdown rendering** — Tables now render with proper styling (rounded border, horizontal scroll wrapper, header background, hover highlight, GFM column-alignment honored). H1 / H2 / H4–H6 sized to match panel scale, HR uses a subtle gradient line, GFM task-list checkboxes themed.
- **OpenCode model selector** — Capability filters now replace instead of stacking, with an All chip and clear-action for empty results. Neutral OpenCode-style dropdown surface with subtle hover/active motion.
- **OpenCode capability help strip** — No layout jump on capability hover; smooth filter-toggle collapse; crossfade text swap when switching between capabilities; descriptions wrap to two lines instead of truncating.
- **Plan-mode tool restrictions (OpenCode)** — Plan mode now uses canonical SDK `body.mode` plus per-message tool restrictions. Plan-mode permission denials render as neutral "Skipped" tiles instead of red errors.
- **Session monitor → Notifications drawer** — Renamed and re-themed. Drawer auto-defaults to the Updates tab when at least one unread item exists, otherwise falls back to Sessions. Internal class names and event names preserved for compatibility.
- **MCP profile sync** — Profile changes now broadcast over WebSocket and reflect immediately in Codex / OpenCode sidepanel dropdowns. File-driven changes (`mcp__SynaBun__profile(action=set)`) and registry activation both route through the same shared path so all profile files stay aligned.
- **Window-id storage GC** — Across Claude, Codex, and OpenCode panels, stale window-scoped tab keys are now garbage-collected on module load (>24h idle, plus an unregistered-key sweep that catches legacy entries from before the registry existed). Significantly reduces server-side state size.
- **Titlebar icon polish** — Notifications swapped to a clean bell glyph; Image Gallery swapped to the universal photo glyph. Removed the dedicated Stale-Loops alert button (loops still surface via the drawer's Loops-tab badge).
- **Backup coverage** — Already shipped earlier; mentioned here for context with the new restart marker work.

### Fixed

- **OpenCode question-tool deadlock with Kimi / non-Anthropic models** — Answering an interactive question card no longer hangs indefinitely when the OpenCode session-processor doesn't resume the LLM stream after the answer is accepted. A 75-second watchdog auto-recovers by aborting the stuck turn and resending the answer as a regular message. Anthropic / Qwen flows clear the watchdog within ~1s as before.
- **OpenCode plan-mode silent stall with Deepseek / non-Anthropic models** — The post-plan action card (Edit / Continue / Compact) now reliably appears via an 8-second finalization watchdog plus multiple terminal-event triggers, even when the plan agent's subagent fires `session.idle` but the parent never finalizes. Recovers from `session.error` and post-stream WS rejections so a half-completed plan isn't stranded.
- **OpenCode plan → build / chat read-only tools with Qwen / non-Anthropic models** — Continuing into implementation after a plan no longer leaves the model with only read-only tools. Build and chat turns now explicitly re-enable write / edit / patch / bash to override OpenCode's session-level tool-restriction persistence.
- **OpenCode subagent progress** — Plan agent dispatching a `task` subagent now shows live child progress (with the subagent's current tool name) instead of stalling for 60–150 seconds with a generic "Thinking…" indicator.
- **OpenCode "Edit plan" empty content** — Edit-plan button now uses a 5-layer fallback chain (cached content → ExitPlanMode tool args → assistant text bubble → reasoning / Thought block → subagent result → server `messages:list` API → disk fallback) so the editor opens with real plan content even when the model surfaced the plan via reasoning or a subagent. Visible error message replaces the prior silent fail.
- **OpenCode "Request message:send timed out" false toast** — WebSocket request timeout bumped from 6 to 30 minutes (Plan agent + subagent runs routinely exceed the old cap). When a timeout does fire while SSE events are still streaming, the red error toast is suppressed and the session is allowed to drive itself to natural completion.
- **OpenCode tray pills hidden on fresh browser tabs** — Cross-window pill discovery now finds sessions saved under any prior window-id and migrates them into the current window on click. ~70 OpenCode / ~14 Codex sessions that previously required a toolbar click to surface now appear in the tray automatically.
- **OpenCode MCP profile dropdown label** — Dropdown label now updates immediately when the active profile changes (via MCP tool, sidepanel API, or file reload), instead of showing the previous profile until next page load.
- **OpenCode sidepanel tables not rendering** — Markdown tables (e.g. comparison tables in agent output) now render with visible borders, scroll wrapper, and proper text contrast. Was a missing-CSS issue, not a parser issue.
- **Sidepanel "no plan file created" with Claude Code** — Post-plan hook now authors the plan markdown file from `ExitPlanMode.input.plan` when the UI failed to capture, and rejects thinking-prefix garbage so plan files don't accumulate as `thought-the-user-wants-…md`. Eager DOM capture tightened so it no longer grabs preamble narration in place of the actual plan.
- **SynaBun loop "no active loop" after `/clear`** — Loop session resolution now verifies flag-file existence before trusting `CLAUDE_SESSION_ID`. New `active-pointer.json` fallback bridges the env gap between hook (live Claude env) and HTTP MCP daemon (stale env) under stateless transport. Stop-hook no longer re-blocks 3× per turn with the journal-update nag after a `/clear`.
- **SynaBun memory tools blocked by permission gate in CLI / PTY sessions** — Enabling SynaBun MCP now auto-injects allow rules for the 7 memory tools across Claude, Codex, Gemini, and OpenCode CLIs. Bare CLI sessions in PTY terminals no longer fall back to native memory or `CLAUDE.md` writes. Inject-only — never overwrites existing user permissions.
- **SynaBun MCP entry survives Claude Code updates** — Session-start hook now self-heals `~/.claude.json` so a `sudo npm i -g @anthropic-ai/claude-code` (which can wipe or strip `mcpServers.SynaBun`) doesn't leave SynaBun disabled until manual re-registration.
- **Duplicate Claude Code hook entries** — Hook installer now dedupes variant command-string forms (relative + absolute) and sweeps existing damage across global + per-project settings on startup. Stop-hook block reasons and recall-context blocks no longer print twice per turn.
- **Restart click after native-module crash** — `Restart Server` now writes a marker file before shutdown so the supervisor respawns even when sqlite / Playwright / node-pty teardown clobbers the sentinel exit code with `mutex lock failed`. Stale markers are cleared on startup so a supervised crash doesn't trigger a spurious respawn.
